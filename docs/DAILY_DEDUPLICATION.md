# 每日订阅的文献去重与日期策略

2026-10-18 起的源码和服务器版本会在模型筛选前排除当前订阅已成功推送的论文。Windows RC5 安装包尚未包含此更新。

## 每日选文

- 每次先合并当前检索的跨来源重复记录，再排除本订阅历史成功发送的论文，最后进行相关性筛选和摘要生成。页面、邮件和自动 Zotero 批次使用同一份最终结果。
- 保留用户设置的起始日期，允许继续补充未发过的历史文献。目标篇数是上限；不足时发送实际数量，不用旧论文补足。
- 没有新增时仍发送通知；邮件区分候选全部已推送、没有合格候选与部分来源异常，并附来源诊断。
- 历史排除按订阅独立执行。修改收件人不清空该订阅历史；不同订阅可推送同一论文。普通单次任务仅执行本次去重，不排除订阅已推送论文。
- 仅成功的正式文献邮件计入历史。SMTP 测试、失败邮件与 CLI `--no-send` 不占用论文；Zotero 导入成功与否不影响邮件推送历史。

## 论文身份

使用全部可用的规范化 DOI、PMID、去版本号 arXiv ID 和来源 ID 匹配，并保留合并记录的身份别名。没有共同编号时，仅在完整标题规范化后相同、标题足够长、存在相同作者且可靠编号不冲突时合并。不会模糊匹配标题，短标题或缺作者的记录也不会仅凭标题合并。

身份不完整或不同来源元数据不一致时仍可能漏判；标题相同也不代表一定是同一篇论文。这次历史回放采用上述保守身份规则，和此前仅统计标题的重复数不完全相同。

## 日期接口

`POST /api/subscriptions`、`PATCH /api/subscriptions/{id}` 和 `POST /api/tasks/{id}/subscription` 支持 `date_to_mode: today | fixed`，读取订阅时返回该字段。

- 新建或任务转订阅默认 `today`：按订阅时区、运行开始时间计算当天截止日，保留起始日期；储存的固定 `date_to` 不参与本次检索。
- `fixed`：沿用用户填写的 `date_to`，空值表示不限。旧订阅缺少该字段时按 `fixed` 读取，不批量改变已有用户意图。
- 执行时在 `subscription_snapshot` artifact 保存投递配置与有效任务日期；排队后修改订阅及重启恢复不改变已有快照。规划 artifact 同时记录有效日期范围。
- `dedupe` artifact 增加 `merged_count`、`history_excluded_count`、`remaining_count`、`history_missing_papers`，保留 `unique_count` 为本次合并后的候选总数。

## 数据和发送边界

迁移 `20261018_0006` 新增 `digest_history`，从全部历史 `digest/sent` 投递及其论文幂等回填，不受页面历史条数限制。历史论文缺失时记录诊断，不推测内容。推送快照独立于普通运行记录保留；删除订阅时一起删除。

SMTP 接受成功后，在同一数据库事务中标记成功并保存论文身份快照。SMTP 已接受但进程在落库前退出的窗口仍无法保证恰好一次发送。回退代码时应停服恢复配套迁移前备份，不能只覆盖运行中的 SQLite 文件。
