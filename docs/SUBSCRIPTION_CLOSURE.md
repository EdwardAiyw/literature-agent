# 无新增时自动暂停与历史文献汇总

此能力属于 Unreleased 源码优化。已发布的 RC7 安装包和此前部署的服务需单独升级，修改源码不会自动更新它们。

## 触发条件

正式订阅运行完成，全部选定来源的诊断均为 `ok` 或 `cached`、无来源错误，结果清单没有规划/筛选/摘要等模型错误，并且最终文献为 0 篇时，自动停用当前订阅。原因分为“候选均已推送”和“没有符合要求的新增文献”。这只反映当前检索范围与来源，并不表示整个领域没有新论文。

来源失败、部分成功、限流、停用、缺少配置、缺少诊断，以及模型异常均不触发暂停。其他订阅继续执行。Fixture、普通单次研究任务、SMTP 测试和 CLI `--no-send` 不触发此流程。

## 邮件与报告

1. 原子保存暂停状态与历史资料快照，后续自动调度跳过此订阅，保留已有任务和历史。
2. 单独发送一封暂停通知，说明原因、时间、成功日报数、去重后文献数及恢复方法。
3. 汇总当前订阅历次成功的正式文献邮件，另发历史汇总邮件。正文包含综合报告，附件包含 UTF-8 `literature-history-report.md`，有可靠编号时同时附 `zotero-identifiers.txt`。

报告包括主题分类、研究方法、主要发现、联系与分歧、研究空白与后续建议，以及完整逐篇参考清单、原文链接、保存的简报、证据提示和原始摘要。综合结论使用 `[P0001]` 等编号引用逐篇清单。资料按批次输入模型，分层合并，完成批次持久保存；较长的摘要拆分输入，逐篇附录保留完整内容，不按页面的 50/100 条历史限制截断。

只纳入本订阅 `digest/sent` 的记录，不纳入失败投递、测试邮件、暂停通知或汇总邮件。优先读取发送时邮件与论文快照；早期记录回退到历史运行记录，再回退到持久论文身份。按项目统一身份规则去重。资料来源、缺失记录、仅有书目信息或简报的篇数明确标注。系统当前未读取论文全文，不能把摘要汇总表述为全文综述；原摘要优先于二手简报，模型提示要求保留局限并区分集合中的不足与领域空白。

模型接口必须返回规定章节及有效引用编号，否则任务失败，页面允许重试；结构和引用检查不等于科学结论已获独立核实。

## 页面操作

- “每日订阅”显示自动暂停原因、时间、历史篇数和通知/汇总状态，每 5 秒刷新。
- 生成报告后可下载完整 Markdown；邮件失败时也可下载已生成的报告。
- 失败时点击“重试通知与汇总”，只继续未成功部分，保留已经成功的通知、已完成批次和报告，不重新检索或导入 Zotero。
- 编辑订阅，勾选“启用每日自动执行”并保存即可恢复。推送历史继续保留；可先修改主题、日期或来源。恢复后的新一次健康空结果会再次自动暂停。

暂停立即生效，即使 SMTP 或汇总失败也不恢复日常执行。失败需要在页面主动重试；服务启动时自动恢复 `queued/running` 的中断汇总，不自动重试已经明确失败的任务。正在通知/汇总时阻止同任务的新运行、删除订阅和本机数据库替换。完成或失败后可以恢复订阅；删除订阅仍会删除其历史及报告。

## 接口与持久化

- `GET /api/subscriptions` 与 `GET /api/subscriptions/{id}` 返回只读 `auto_pause`：`run_id`、`paused_at`、`reason`、`status`、`error`、`paper_count`、`report_ready`。
- `POST /api/subscriptions/{id}/closure/retry`：仅重试失败任务，返回 202；活动/完成任务返回 409。
- `POST /api/subscriptions/{id}/closure/start`：按用户明确要求暂停并汇总已有的最近一次 0 篇订阅运行，不重跑检索；最近运行须已完成且为 0 篇，否则返回 409。此操作允许有来源提示的历史空结果，原因标为 `user_requested`，通知和报告保留异常说明；自动触发条件保持不变。重复请求复用原报告任务，不重复发信。
- `GET /api/subscriptions/{id}/closure/report`：下载已生成报告，未就绪返回 404。
- 投递类型新增 `pause_notice`、`history_summary`，继续使用 `pending/sent/failed` 状态；不写入论文推送去重历史。
- 在现有 `run_artifacts` 中以 `subscription_closure` 保存不可变资料范围、进度、批次缓存、报告和投递 ID；订阅 JSON 保存暂停原因与运行指针，无需新增数据库迁移。

SMTP 接受成功表示服务器接受，不等于收件箱确认到达。已成功落库的邮件在重试时跳过；SMTP 已接受、进程在记录成功前崩溃的窗口仍可能产生重复投递，与现有日报的发送边界一致。
