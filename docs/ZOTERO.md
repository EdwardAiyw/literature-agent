# Zotero 联动

RC4 源码和安装包包含从工作台逐篇导入 Zotero 的功能及本轮修复。旧 RC3 安装包不包含 Zotero 联动；RC4 安装包已由 Windows Release 工作流在回归及打包检查通过后生成并发布。

## 配置

1. 打开 Zotero 的 [API Keys 设置](https://www.zotero.org/settings/keys)。个人文献库使用页面显示的 User ID；群组文献库使用群组 ID。
2. 创建或使用已有的 API Key，允许读取和写入目标文献库。
3. 在 Literature Agent 的“设置 → Zotero 文献库”选择个人或群组类型，填写 Library ID、API Key 和分类名称。
4. 如需写入指定已有分类，可填写其 8 位 Collection Key；填写后分类名称不再决定目标分类。
5. 点击“测试 Zotero 连接”，确认读写权限；点击“保存 Zotero”。测试只读取权限及文献库，不创建分类或条目。

API Key 保存在当前 Windows 用户的凭据管理器；设置响应和普通设置文件不会包含密钥。Zotero 为可选配置，不影响首次设置或普通检索。

## 导入

在工作台的论文行点击“导入 Zotero”。导入仅传输该论文现有的标题、作者、摘要、日期、DOI、链接和来源标签。

- 相同 DOI（不区分大小写，兼容 DOI URL）复用已有条目。有 DOI 时分页读取目标库的顶层条目并比较 DOI 元数据；Zotero 快速搜索不搜索该字段。没有 DOI 时按标题检索后匹配完整标题。
- 复用已有条目时仅补充目标分类，不覆盖用户修改过的标题、摘要或其他字段。
- 未填写 Collection Key 时，会复用或创建与分类名称完全一致的分类。
- 每篇记录成功、已有条目或失败状态；失败后可重试。保存新的目标文献库或分类后，立即清除旧状态并重新读取该目标的记录，已完成任务也会刷新；旧请求延迟返回不会恢复旧链接。切回原目标会恢复原目标的记录。未保存或保存失败的编辑不改变目标；清除 API Key 会清除显示状态并停用导入。
- “精读”“保存”等审核标签不会自动导入；“忽略”的论文禁止导入。
- 导入书目信息，不下载 PDF，不发送邮件。后续可在 Zotero 中自行获取附件。

这里使用 Zotero 在线 Web API，桌面 Zotero 不必运行。若要在桌面查看结果，请登录对应账号并同步；离线本地库不会自动收到云端条目。成功条目优先提供 Zotero 返回的网页链接；没有网页链接时提供桌面 Zotero 定位链接。

DOI 查重最多需要读取整个文献库，大库首次检查或未命中时可能较慢。每次导入重新读取，不使用可能遗漏外部修改的本地索引；查重中途失败时不会创建分类或条目。同一服务进程内，导入、切换数据目录和恢复备份互斥，冲突返回 409，完成后可重试。此锁不能阻止其他 Zotero 客户端同时新建相同论文。

## 迁移旧项目配置

在项目根目录执行：

```powershell
.\backend\.venv\Scripts\python.exe .\scripts\migrate-zotero-config.py ..\literature-digest\.env
```

脚本先以只读请求检查旧配置的文献库访问和写入权限，通过后将配置保存到当前项目的数据目录，并把 API Key 放入 Windows 凭据管理器。它不会覆盖已配置的 Zotero 连接，也不会向 Zotero 写入论文。迁移后重启服务。

## 排查

- 401：Key 无效或已撤销。
- 403：检查 Library ID、个人/群组类型以及 Key 的目标库读写权限。
- 404：检查指定分类或文献库是否存在。
- 409（本地接口）：导入或数据库维护正在进行，完成后重试。
- 412：Zotero 写入前置条件冲突，可能是条目版本变化或写入令牌已使用；重试会先重新查重及读取版本。
- 429：Zotero 限流，稍后重试。
- 网络失败：确认可以访问 `https://api.zotero.org`。

导入状态代表最后一次操作结果；若在 Zotero 中删除或移动了条目，可点击“检查 Zotero”再次确认目标分类。删除后重新导入会使用新的创建令牌；写入成功但响应丢失时，重试会通过查重复用已创建的条目。本功能不自动删除远端重复条目。
