# Zotero 联动

当前源码和服务器支持逐篇导入、按任务自动导入指定集合，以及每日邮件标识符附件。自动导入和附件是 RC5 发布后的源码更新，不在既有 RC5 Windows 安装包中；已发布安装包和标签保持原样。

## 配置

1. 打开 Zotero 的 [API Keys 设置](https://www.zotero.org/settings/keys)。个人文献库使用页面显示的 User ID；群组文献库使用群组 ID。
2. 创建或使用已有的 API Key，允许读取和写入目标文献库。
3. 在 Literature Agent 的“设置 → Zotero 文献库”选择个人或群组类型，填写 Library ID、API Key 和分类名称。
4. 如需写入指定已有分类，可填写其 8 位 Collection Key；填写后分类名称不再决定目标分类。
5. 点击“测试 Zotero 连接”，确认读写权限；点击“保存 Zotero”。测试只读取权限及文献库，不创建分类或条目。

Windows API Key 保存在当前用户的凭据管理器；服务器保存在权限受限的密钥文件。设置响应和普通设置文件不会包含密钥。Zotero 为可选配置，不影响首次设置或普通检索。

## 每日自动导入指定集合

1. 在创建/编辑任务或每日订阅时，点击“读取集合”。下拉列表显示集合完整父路径和唯一 Key。
2. 选中目标集合，勾选“检索完成后自动导入 Zotero”，保存。开启时必须提供有效的已有 Collection Key，不按名称猜测或自动新建集合。全局文献库和 API Key 仍在设置页共享。
3. 已有任务转为每日任务时沿用其导入配置。所有新旧任务默认关闭自动导入，须按任务开启。
4. 检索成功后先保留持久导入批次，再尝试发送邮件，之后处理导入。邮件失败不阻止导入；导入失败不改变检索成功状态。普通单次任务开启此选项后也会自动导入。
5. 工作台显示新增、已有、失败、跳过和待处理数量。点击“重试失败条目”只处理该批次未成功的论文，不重新检索、不重复发邮件。也可手动“导入本次结果到任务集合”补导已完成运行。

批次固定运行 ID、目标库/集合及论文范围，保存每篇进度。改动任务集合后，已有批次仍使用原目标；更换全局文献库后，原批次须恢复原库配置才能重试。重启恢复排队/处理中批次，并重新读取远端索引。已成功条目保持原结果；写入响应丢失的失败条目会重新查重。“忽略”的论文跳过，已有 Zotero 条目仅补充集合成员关系，不覆盖其他字段或移除原集合。

每个批次每次尝试分页读取一次目标库，构建共用 DOI/标题索引，并核实导入后集合成员关系。失败会结束本轮尝试，剩余条目标为失败，待用户重试；429 不会无限自动请求。单服务实例内批次、逐篇导入及数据库替换互斥；排队批次也阻止任务删除、数据库替换。其他 Zotero 客户端仍可能并发修改条目。

## 邮件附件和手动标识符导入

每日摘要在有可靠编号时附带 UTF-8 `zotero-identifiers.txt`，每行一个编号，可整体粘贴到 Zotero 的“通过标识符添加条目”窗口；请先选中目标集合。工作台“下载标识符 TXT”可导出既有运行，无需补发邮件。

- 每篇优先选择一个已有编号：DOI → PMID → arXiv ID → ISBN → ADS 条码，然后去重。ISBN 校验校验位；arXiv 去除版本号。不会从标题推测或编造编号。
- 支持从已有 metadata/外部 ID 提取；支持这些编号不代表额外接入 ISBN/ADS 检索源。Semantic Scholar 外部 ID 和 OpenAlex PMID 会保留供导出。
- 缺少可靠编号的论文在邮件正文列明；没有可用编号时说明原因，不附空文件。已忽略论文不导出。SMTP 测试邮件不附文献文件。
- 文件仅包含编号，不包含标题、注释或 PDF。自动导入成功的条目无需再次粘贴；Zotero 自身的编号识别和文献元数据覆盖率仍取决于其上游服务。

## 源码 API

| 接口 | 用途 |
| --- | --- |
| `GET /api/zotero/collections` | 只读分页列出已有集合，返回 `key/name/path` |
| `POST/PATCH /api/tasks`、`/api/subscriptions` | `zotero_auto_import` 与 `zotero_collection_key` 配置（PATCH 追加资源 ID） |
| `GET /api/runs/{id}/zotero-identifiers` | 下载 UTF-8 TXT，响应头 `X-Missing-Identifier-Count` 记录缺少编号数量 |
| `GET/POST /api/runs/{id}/zotero-batches` | 读取批次/对当前任务集合创建幂等批次；仅完成的运行可导入 |
| `POST /api/runs/{id}/zotero-batches/{batch_id}/retry` | 按原目标重试失败条目 |

批次存储于既有 `run_artifacts`，节点名为 `zotero_batch.<destination hash>`，自动目标快照为 `zotero_target`；无需新增表或修改历史运行。`zotero_imports` 继续按论文及目标记录逐篇状态。

2026-10-17 已通过 182 项后端 CI 测试、30 项 Edge 全量回归及真实服务器集合归属验收；详见 [本次验证记录](ZOTERO_VALIDATION_2026-10-17.md)。

## 导入

在工作台的论文行点击“导入 Zotero”。导入仅传输该论文现有的标题、作者、摘要、日期、DOI、链接和来源标签。

- 相同 DOI（不区分大小写，兼容 DOI URL）复用已有条目。有 DOI 时分页读取目标库的顶层条目并比较 DOI 元数据；Zotero 快速搜索不搜索该字段。没有 DOI 时按标题检索后匹配完整标题。
- 复用已有条目时仅补充目标分类，不覆盖用户修改过的标题、摘要或其他字段。
- 逐篇导入优先使用任务指定的 Collection Key；任务未指定时沿用全局设置。两者都未填写 Key 时，会复用或创建与全局分类名称完全一致的分类。此名称回退不适用于自动批次。
- 每篇记录成功、已有条目或失败状态；失败后可重试。保存新的目标文献库或分类后，立即清除旧状态并重新读取该目标的记录，已完成任务也会刷新；旧请求延迟返回不会恢复旧链接。切回原目标会恢复原目标的记录。未保存或保存失败的编辑不改变目标；清除 API Key 会清除显示状态并停用导入。
- “精读”“保存”等审核标签不会自动导入；“忽略”的论文禁止导入。
- 导入书目信息，不下载 PDF，不发送邮件。后续可在 Zotero 中自行获取附件。

这里使用 Zotero 在线 Web API，桌面 Zotero 不必运行。若要在桌面查看结果，请登录对应账号并同步；离线本地库不会自动收到云端条目。成功条目优先提供 Zotero 返回的网页链接；没有网页链接时提供桌面 Zotero 定位链接。

DOI 查重最多需要读取整个文献库，大库首次检查或未命中时可能较慢。逐篇导入每次重新读取，不使用跨调用的本地索引；查重中途失败时不会创建分类或条目。批次则每次尝试共用一个新建的远端索引。同一服务进程内，导入、切换数据目录和恢复备份互斥，冲突返回 409，完成后可重试。此锁不能阻止其他 Zotero 客户端同时新建相同论文。

## 迁移旧项目配置

在项目根目录执行：

```powershell
.\backend\.venv\Scripts\python.exe .\scripts\migrate-zotero-config.py ..\literature-digest\.env
```

脚本先以只读请求检查旧配置的文献库访问和写入权限，通过后将配置保存到当前项目的数据目录，并把 API Key 放入 Windows 凭据管理器。它不会覆盖已配置的 Zotero 连接，也不会向 Zotero 写入论文。迁移后重启服务。

## 排查

- 401：Key 无效或已撤销。
- 403：检查 Library ID、个人/群组类型以及 Key 的目标库读写权限。
- 404：检查指定分类或文献库是否存在。
- 409（本地接口）：导入或数据库维护正在进行，完成后重试。
- 412：Zotero 写入前置条件冲突，可能是条目版本变化或写入令牌已使用；重试会先重新查重及读取版本。
- 429：Zotero 限流，稍后重试。
- 网络失败：确认可以访问 `https://api.zotero.org`。

导入状态代表最后一次操作结果；若在 Zotero 中删除或移动了条目，可点击“检查 Zotero”再次确认目标分类。删除后重新导入会使用新的创建令牌；写入成功但响应丢失时，重试会通过查重复用已创建的条目。本功能不自动删除远端重复条目。
